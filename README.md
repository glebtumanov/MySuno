# MySuno — локальный генератор музыки (прототип v0.1)

Однопользовательское веб-приложение: русскоязычные промпты → музыка на open-source модели
**[ACE-Step 1.5](https://github.com/ace-step/ACE-Step-1.5)** (MIT) на GPU или CPU. Всё работает локально,
сервер слушает только `127.0.0.1`.

## Быстрый старт

```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1   # один раз: Python, зависимости, веса (~10–15 ГБ)
run.bat                                              # запуск; откроется http://127.0.0.1:8000
```

Права администратора не нужны. Если Hugging Face недоступен — включите VPN на время `setup.ps1`.

## Что умеет

| Раздел | Возможности |
|---|---|
| **Создать** | русское описание, жанры (мультивыбор), настроение, **негативные жанры**, вокал (авто / мужской / женский / детский / хор / дуэт / без вокала), русский текст песни или авто-текст от LM, длительность 10–300 с, температура, расширенные: варианты (1–4), seed, шаги, guidance, BPM, формат, папка; очередь с прогрессом |
| **Библиотека** | одноуровневые папки (создать/переименовать/удалить), список треков, плеер с перемоткой и автопереходом, переименование, перенос в папку, скачивание, удаление, «повторить с этими параметрами», подробности (caption, текст, seed) |
| **Настройки** | сведения о железе, устройство (авто / GPU / CPU), DiT (turbo / sft / base), LM (авто / выкл. / 0.6B / 1.7B), бэкенд LM, ускоренный LM-декодер, предзагрузка при старте, offload, INT8, формат, лимит длительности, загрузка/выгрузка моделей |

Выполняющуюся генерацию можно **остановить** кнопкой в очереди (срабатывает за ~0.5 с — проверка идёт на каждом токене LM).
При фатальной ошибке CUDA движок помечается неисправным и просит перезапустить сервер (дальше продолжать нельзя — контекст GPU повреждён).

### Как русский промпт попадает в модель
1. Выбранные жанры, настроения и вокал → английские теги (`mysuno/presets.py`).
2. Свободное русское описание → перевод ru→en **на CPU** (`Helsinki-NLP/opus-mt-ru-en`).
3. Итоговый английский `caption` уходит в ACE-Step. Русский текст песни передаётся как есть (`vocal_language="ru"`).
   Если текста нет и включён авто-текст — его пишет LM-планировщик ACE-Step.

### Негативные жанры — экспериментально, надёжно не работает
У ACE-Step нет настоящего negative-prompt для диффузионной части (turbo вообще без CFG). Негативные жанры
(1) убираются из позитивных тегов и (2) передаются в `lm_negative_prompt` LM-планировщика.
**A/B-тест (4 seed'а, оценка CLAP «насколько звучит тяжело»): без негативных 88 %, с негативными 88 %** (при LM-CFG 5 —
79 % vs 91 %, т.е. шум). Заметного эффекта нет. Реальный способ — подмена «пустого» условия в CFG диффузионной модели
на негативный caption (только base/sft) — запланирован.

### Температура
Это `lm_temperature` LM-планировщика (0–2). Действует, когда включено «LM-планирование».

### Автотекст
Если текст песни пуст, а вокал включён, текст пишет LM-планировщик ACE-Step 1.7B. Он справляется слабо
(встречаются выдуманные слова), поэтому для серьёзной работы лучше вводить свой текст.
Вокал по-русски при этом разборчив: Whisper распознал 88–96 % слов эталонного текста в сгенерированных треках.

Модели при запуске сервера загружаются и прогреваются в фоне (~30 с), поэтому первый трек стартует сразу
(настройка «Загружать и прогревать модели при запуске»). Воспроизвести замеры: `python scripts/bench.py`
при запущенном сервере; фазы внутри генерации — `python scripts/profile_lm.py` (сервер остановить).

### Откуда ускорение с LM-планированием (×2.1)
Раньше 75% времени уходило на LM-планировщик: PyTorch-бэкенд ACE-Step декодировал ~25 мс/токен — это накладные расходы
запуска ~1000 мелких CUDA-ядер на токен, а не пропускная способность памяти (vLLM, flash-attn и Triton под Windows
недоступны). Что сделано:

1. **Свой декодер Qwen3 на CUDA Graphs** (`mysuno/fastlm.py`): статический KV-кэш, шаг декодирования захвачен в граф,
   q/k/v и gate/up склеены (view'ы на те же веса — без доп. VRAM), GQA без копирования KV, `lm_head` выровнен до кратного 128.
   В фазе аудио-кодов `lm_head` считается только по допустимым токенам (коды + EOS), что даёт ещё −0.5 мс/токен.
   Подключается подменой одного метода `_forward_pass` (`mysuno/lmhandler.py`) — вся логика ACE (CFG, FSM, сэмплирование)
   остаётся оригинальной; при любой несовместимости (CPU, offload, не хватило кэша) — прозрачный откат на штатный путь.
   Результат: 40 → ~100 токенов/с.
2. **`gc.freeze()` после загрузки моделей**: ACE вызывает `gc.collect()` три раза за трек, и каждый обходил все объекты
   моделей (~0.33 с). −1 с на трек.
3. **VAE-тайл 512** вместо 128 на карте с запасом памяти: −0.5 с на 120 с аудио.
4. Прогрев после загрузки и фоновый прогрев переводчика: первый трек не медленнее остальных.

**Проверка качества** (не «на слух», а измеримо): на реалистичной фазе кодов с CFG KL-дивергенция распределения к fp32-эталону
у быстрого декодера 0.0650, у штатного HF bf16 — 0.0658 (`scripts/check_fastlm_codes.py`); разборчивость русского вокала по Whisper
на 8 seed'ах: точность слов 90% (быстрый) против 88% (штатный). Переключатель «Ускоренный LM-декодер» в настройках позволяет сравнить.

Потолок дальше: матмулы уже на ~65% пропускной способности памяти (3.7 ГБ весов за токен), остальное — ~1400 мелких
элементных ядер без компилятора (Triton под Windows блокирует Smart App Control) и цикл ACE с синхронизацией на каждом токене.
Следующие шаги: свой цикл сэмплирования в графе (≈ −10%), квантование весов (рискованно для качества).

## Качество: что реально на него влияет (измерено)

После ускорения возникла жалоба «иногда набор шумов». Я проверил это не на слух, а измеримо
(`mysuno/quality.py`, `scripts/quality_lab.py`, ~600 сгенерированных треков):

* **Быстрый LM-декодер не виноват** — CE/PQ идентичны штатному на 120 и 300 с (KL к fp32 равен).
* Причины были другие: **длина 300 с** (документация ACE: > 4 мин — повторы и проблемы структуры),
  **«суп» из противоречивых тегов** (3 жанра + 3 несовместимых настроения) и **зацикливание аудио-кодов LM**:
  у вас в библиотеке 1 трек был чистым шумом (флэтность 0.19 против 0.001–0.05 у музыки) и 4 — статичными дронами
  (72–97% неизменных 10-секундных окон).

Метрики: Audiobox Aesthetics (Meta, обучена на оценках людей: PQ/CE), CLAP (соответствие описанию), Whisper (разборчивость
русского текста), спектральная флэтность и «статичность». Что дало эффект:

| Рычаг | Результат | В приложении |
|---|---|---|
| **Лучший из N** вариантов (отбор по Audiobox + CLAP + Whisper) | средний балл выбранного: N=1 7.28 → N=2 7.58 → N=4 7.67 → **N=8 7.75** | режимы «Хорошо ×4», «Максимум ×8» |
| **CFG LM-планировщика 4.0** вместо 2.0 | на 300 с: 7.18 → 7.6–7.7; дронов 21% → 8% | по умолчанию |
| **LM переписывает caption** (`cot_caption`) | на «грязных» наборах тегов +0.5 (house/techno: шум 19% → 3%) | по умолчанию |
| **Страж против брака** | одиночный трек со случайным seed перегенерируется (до 2 раз) при шуме/дроне | по умолчанию |
| Предупреждения о противоречивых тегах, > 3 жанров, > 4 минут | — | в форме |
| **Подготовка текста**: «[Куплет]/[Припев]» → `[Verse]/[Chorus]`, пустые строки, авто-разметка | русские теги ACE может спеть как слова | кнопка + автоматически при отправке |

Что **не** помогло (проверено): XL-модели (XL-turbo 7.26, XL-sft 6.86 против turbo 7.44, при времени ×3–6), sft-DiT (7.18; зато лучше
следует описанию: CLAP 0.50 против 0.44), ADG (6.99), CFG DiT 4–9, LM 4B (7.32 против 7.53 у 1.7B), LM 0.6B (6.93),
низкая температура LM 0.7 (хуже: больше дронов). **Негативные жанры** не работают даже при CFG 5 — остаются «экспериментальными».

Практические советы: 1–3 минуты надёжнее 5; один-два жанра; не смешивать «спокойное» и «энергичное»; для вокала —
короткие строки (6–10 слогов) и теги секций; «Максимум» стоит включать для важных треков.

## Использование железа

| Устройство | Роль |
|---|---|
| **NVIDIA GPU (CUDA)** | DiT + LM. Профиль «авто» берёт настройки из таблицы ACE-Step по объёму VRAM; на 16-ГБ карте со свободной памятью всё держится на GPU без offload и квантования. При нехватке памяти — автоповтор в экономном режиме (offload + INT8 + LM 0.6B) |
| **CPU** | перевод промптов, кодирование, очередь; полноценный CPU-режим (`Настройки → Устройство → CPU`, LM выключен) — работает, но медленно |
| **ОЗУ** | модели держатся резидентно между генерациями |
| **AMD iGPU** | не используется (ROCm не поддерживает встроенные Radeon на Windows, DirectML замедлит) |

           + web/ (HTML/CSS/JS без сборки)

           bench.py           — замеры скорости по HTTP;   api_e2e.py / api_stress.py — сквозные тесты (батчи, длинные, отмена)

## Windows-нюансы (почему так устроено)
- **Smart App Control** блокирует неподписанные бинарники, поэтому используется официальный подписанный Python 3.12
  в `python/`, а не Python из `uv` (python-build-standalone). Отключать защиту Windows не требуется.
- Десктопное приложение Claude виртуализирует запись в `AppData`; кэш и Python держатся внутри папки проекта.
- MP3 кодируется через libsndfile (`soundfile`), поэтому `ffmpeg` не нужен (ACE-Step сам требует `ffmpeg.exe` для MP3).

## Проблемы
- `CUDA не найдена` — обновите драйвер NVIDIA; для RTX 50xx нужен torch с `cu128` (стоит по умолчанию).
- Нехватка VRAM — в «Настройках» включите offload и INT8 либо LM 0.6B/«выкл.».
- Первая генерация долгая — загружаются веса; дальше модели резидентны.
